# 🦁 3주차: 객체지향 II - 상속과 다형성 (다형성 구조 설계하기)

역할을 묻는 조건문 대신, 역할을 가진 객체에게 판단을 맡기는 **다형성 구조**를 설계하며 객체지향의 핵심인 상속과 추상화를 직접 경험하는 자바 프로그래밍 과제입니다.

자세한 내용은 PBL 사이트를 참고 하세요. [3주차 - 객체지향 II - 상속과 다형성]([https://likelion-pbl-five.vercel.app/](https://likelion-pbl-five.vercel.app/springboot/2f044860a4f481869998cc607120d4c4))

## 🎯 과제 목표
* **상속과 추상화**: 공통 속성을 부모 클래스로 분리하고 추상 클래스와 인터페이스의 차이를 이해합니다.
* **다형성 활용**: 조건문(`if-else`) 없이 객체의 타입에 따라 다른 동작을 수행하는 구조를 설계합니다.
* **유연한 설계**: 인터페이스를 통한 정책 분리가 코드의 유지보수에 미치는 영향을 학습합니다.
* **확장성 체감**: 2주차의 `Lion` 클래스가 상속 구조 속에서 어떻게 확장되는지 비교 분석합니다.

## 🛠 기술 스택
* **Language**: Java (JDK 17 이상)
* **Environment**: Console (CLI)
* **Key Concepts**: Inheritance, Abstraction, Polymorphism, Interface

## 📋 주요 기능
1. **역할별 객체화**: 아기사자(`Lion`)와 운영진(`Staff`)의 공통점과 차이점을 상속 구조로 설계
2. **정책 기반 판단**: 인터페이스를 활용하여 각 역할별 과제 제출 가능 여부(Policy)를 결정
3. **정보 통합 출력**: 다형성을 활용하여 타입에 관계없이 객체의 상세 정보와 권한을 콘솔에 출력

## 🚀 실행 흐름 (Implementation Logic)
본 미션은 역할을 묻는 코드 대신 객체에게 책임을 위임하는 구조로 나아가는 과정을 구현합니다.

| 단계 | 주요 작업 내용 |
| :--- | :--- |
| **Step 1** | 추상 클래스 생성 및 공통 속성(이름, 전공, 기수, 파트) 정의 및 상속 |
| **Step 2** | 과제 제출 정책 인터페이스 생성 및 역할별 구현체(True/False) 작성 |
| **Step 3** | 추상 메서드를 통해 하위 클래스가 자신의 정책과 정보를 스스로 반환하도록 구현 |
| **Step 4** | `Main`에서 추상 클래스 타입으로 객체를 다루며 다형성 원리 확인 |

## ⚠️ 제약 사항 및 유의 사항
- [ ] **조건문 사용 금지**: `if/else`, `switch` 등을 사용하여 역할을 구분하지 않습니다.
- [ ] **타입 체크 금지**: `instanceof`를 사용하여 객체의 타입을 강제로 확인하지 않습니다.
- [ ] **로직 위임**: 과제 제출 가능 여부 판단을 `Main`이 아닌 각 객체의 `Policy`에 맡깁니다.
- [ ] **패키지 준수**: 지정된 패키지 구조(`role`, `policy`)를 반드시 지켜야 합니다.
- [ ] **캡슐화 유지**: 부모 클래스의 필드는 `private`으로 유지하며, 자식 클래스에서의 접근 방식을 고민합니다.
